\subsection{Is Ignorance Truly Strength?}
\label{sec:background-mechanism}

Existing systems are built around a common assumption: 
applications need not be involved in scheduling decisions.

\paragraph{Kernel schedulers limit applications to coarse-grained 
scheduling classes and millisecond-scale enforcement}
Monolithic kernels such as Linux implement a fixed set of scheduling policies via scheduling \textit{classes}~\cite{linux_sched}, such as the Completely Fair Scheduler (CFS) for best-effort tasks and the Real-Time (RT) scheduler for latency-sensitive tasks.
While these classes cover a range of workloads, they provide no means for applications to express their scheduling intent or policies tailored to their specific SLOs.
Applications can select a scheduling class and set parameters such as priority levels.
For example, an application can choose the RT class and assign a priority of 10 to a latency-sensitive thread, while another thread in the same application can use the CFS class with default parameters for best-effort tasks.
However, these classes are fixed and limited in number, and the parameters they expose are coarse-grained, such as static priority levels or time slices.
Beyond the limited expressiveness, kernel scheduling decisions are made at millisecond-scale granularity, which is too coarse for microsecond-scale SLOs.

\paragraph{Programmable kernel schedulers improve policy flexibility but 
remain constrained to millisecond-scale granularity}
Recent research has proposed programmable kernel schedulers that allow applications to define custom scheduling policies~\cite{humphries2021ghost,linux-sched-ext}.
These systems provide a more flexible interface for applications to specify scheduling policies, such as by allowing user-space code to be invoked at scheduling decision points.
However, they still operate within the kernel's scheduling framework and are subject to the same millisecond-scale scheduling granularity, limiting their effectiveness for microsecond-scale SLOs.

\paragraph{Dataplane OSes seize full scheduling control, without any interfaces for applications to express their intent}
To achieve microsecond-scale scheduling, recent research has proposed specialized dataplane OSes that bypass the kernel~\cite{kaffes2019shinjuku}.
While these systems can achieve low-latency scheduling purely in user space, they do so by seizing full control over scheduling with no interface for applications to express their intent.
Specifically, they hardcode a single scheduling policy for all workloads, typically a hybrid of FCFS and PS optimized solely for tail latency.
As a result, applications with diverse SLOs have no interface to customize scheduling behavior without invasive modifications to the OS itself.

\paragraph{\sysname approach: decoupling scheduling intent, policy, and enforcement}
The rigidity of state-of-the-art dataplane OSes stems from \textit{conflating three distinct concerns}: scheduling intent, policy, and enforcement.
Scheduling intent refers to the high-level goals that applications have for their scheduling behavior, such as minimizing tail latency or meeting deadlines.
Scheduling policy is the algorithmic strategy that realizes this intent, such as SRPT or EDF.
Scheduling enforcement is the mechanism by which the OS implements the policy, such as a kernel scheduler or a user-space runtime.
Existing systems conflate these concerns by hardcoding a single policy and enforcement mechanism that may not align with the diverse intents of different applications.
\sysname's key insight is that by decoupling these concerns, we can enable applications to express their scheduling intent and policy in a high-level, declarative manner, while allowing the OS to automatically synthesize efficient enforcement mechanisms tailored to those policies.
